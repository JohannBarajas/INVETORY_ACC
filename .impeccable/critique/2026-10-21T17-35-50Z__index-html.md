## Design Specificity Verdict

The brand layer is authored for this product: yellow Sell tag, receipt-style mono numbers, red reorder box, WhatsApp day summary, ID + code sign-in, "You're at" store header. The interaction model is generic: alphabetical list, substring search, two-step modal. It works against the product's own "finding beats browsing" principle. Every case placeholder reads "C", so the visual ID column carries no information where the main pain point is.

Deterministic scan: 0 findings on index.html / app.js (template strings). On rendered pages: dark-mode placeholder contrast 3.5:1 (real; no ::placeholder rule), kicker-above-heading (false positive: documented eyebrow), nested-cards on #picks (false positive: list inside a sheet). styles.css vs DESIGN.md: 24 off-ramp font sizes and 1 undocumented scrim color (minor drift); thumbnail radius hits were a DESIGN.md frontmatter gap, now fixed.

## Priority Issues

- **[P0] Finding an item doesn't scale.** Substring search, alphabetical list, "C" placeholders, no autofocus or price in the sell picker, names wrap 2–3 lines. Fix: autofocus picker search; recent/top sellers on empty query; type chips (Cases / Glass / Chargers / Cables); model-aware, bilingual matching ("funda 16 pro"); distinct placeholders; cost/price off the row. Command: shape, then optimize.
- **[P0] No Spanish / i18n layer.** A confirmed requirement; all strings inline, en-US locale hard-coded, Spanish expansion pushes the header to ~37% of the screen. Fix: string table + t(), language toggle, Intl for money/time, collapse header links into a menu. Command: harden (+ adapt).
- **[P1] Stock changes and voids lack status and undo.** Silent debounced saves, wrong count on failure, double-tappable "Sure?", no undo. Fix: per-row saving/saved state with revert on error; Undo toast for sale/void/stock; void confirm that names the item and amount; offline banner. Command: harden.
- **[P1] Store-screen header buries the list and splits the jobs.** 3 header links + search + reorder box + Today leave ~1.5 rows visible; Log out beside Change store with no confirm; store name clips under the search at 375px. Fix: header = store name + search; links into a menu; reorder box as a one-line filter chip; sell from a row. Command: layout, then distill.
- **[P2] Accessibility gaps.** Sheets lack dialog semantics/focus trap; searches have no label; stepper labels don't name the item; count changes not announced; yellow focus ring ~1.6:1 on white; Void target 40px; dark-mode placeholders 3.5:1. Command: audit, then harden.

## Persona Red Flags

- **Casey (one-handed):** search, Change store and Log out at the top; Log out one tap; backdrop tap loses the sale; Void → Sure? double-tappable; scroll-taps can change stock silently.
- **Alex (power user):** three items = three full sheet cycles; no recents, sell-from-row, Enter-to-pick or scan; price re-confirmed every time.
- **Sam (screen reader):** sheets not announced, focus not moved; steppers read "Remove one" with no item; stock changes silent; low stock is color-only; focus ring nearly invisible in light mode.
- **Spanish-dominant counter employee:** every word English, Supabase errors included; "Void", "Sure?", "Alert when fewer than" are guesswork; "funda 16" finds nothing; Spanish-locale price input shows "19,99" next to "$19.99".

## Minor Observations

- "tap to see" stays visible when Today is open.
- Sell picker mixes sold-out items in; sort them last, as the catalog does.
- Reorder box rows aren't tappable.
- Two names for owner tools ("⚙ Employees" vs "Settings, employees and store names").
- Toast shows a new employee's code in plain text; revealed PINs are readable over the shoulder.
- Edit sheet stock is absolute while the stepper is a delta: two mental models.
- 24 font sizes off the documented ramp (14/15/18/22/28/32/44px).

## Questions to Consider

- If most sales are the same 20 items per store, why does the counter screen open on an alphabetical ledger instead of this store's top sellers?
- Should staff see Cost on every row, or is the main list the owner's spreadsheet in a counter app's clothes?
- What if search were bilingual and model-aware, so naming conventions become the app's job, not the employee's memory?
